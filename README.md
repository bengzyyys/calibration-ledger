# 本地器具校准与证书台账

在本机运行的器具校准台账：登记器具、录入校准证书、申请使用器具、安排校准计划、
按器具核对结果。数据只保存在用户指定的本机文件中，不连接任何真实实验室；
退出后再次打开同一台账可继续查询与操作，不同台账文件之间的数据互不混入。

## 构建与测试

```bash
go test ./...
go build ./cmd/ledger
```

原有的 `calibrate.Ready()` 公开入口保持不变。

## 命令行用法

所有子命令都通过 `-f/--file` 指定台账文件（默认当前目录 `ledger.json`），
加 `--json` 可输出机器可读结果。退出码：`0` 成功；`1` 业务拒绝或编号不存在；
`2` 参数或文件读写错误。

```bash
# 登记器具：编号、名称不能为空；允许的绝对误差必须是不小于零的有限数。
# 新器具自动处于“待校准”状态，编号重复会被拒绝。
ledger -f 我的台账.json register --id M-001 --name 数字万用表 --allowed 0.5

# 切换状态：在用、停用、待校准。切换为在用不代表已校准；停用不删除证书与使用记录。
ledger -f 我的台账.json status --id M-001 --status 在用

# 录入证书：日期必须是实际存在的 YYYY-MM-DD；校准日期不能晚于本机今天；
# 截止日必须晚于校准日期。证书编号全台账唯一。
ledger -f 我的台账.json cert \
  --instrument M-001 --number C-2026-01 \
  --cal-date 2026-09-01 --expiry 2027-09-01 \
  --method JJF规范 --error -0.4 --summary 例行校准

# 申请使用：只有“在用 + 最近证书合格 + 未到期”才允许；拒绝时列出全部原因。
# 无论允许还是拒绝都会留痕；未知编号报错且不留痕。
ledger -f 我的台账.json use --id M-001

# 按器具核对：登记信息、当前能否使用及原因、最近证书、全部历史证书、被拒绝记录。
# 同时展示该器具当前及已结束的校准计划、改期记录和关联证书编号。
ledger -f 我的台账.json review --id M-001

# 列出全部器具
ledger -f 我的台账.json list

# 建立校准计划：计划编号全台账唯一（已结束计划的编号也不能复用），
# 日期必须真实存在且不早于本机今天，说明非空；每件器具最多一项未结束计划。
ledger -f 我的台账.json plan \
  --instrument M-001 --number PL-2026-01 --date 2026-10-20 --note 年度例行校准

# 计划改期：未结束的计划可改期，新日期不能早于操作当天，原因非空；
# 每次改期前后的日期、操作时间和原因都会留痕。
ledger -f 我的台账.json reschedule --number PL-2026-01 --date 2026-11-05 --reason 实验室排期冲突

# 取消计划：保留原计划、取消时间和原因，不再列入待办，也不能重新开启。
ledger -f 我的台账.json cancel --number PL-2026-01 --reason 暂停送检

# 用证书完成计划：证书必须属于该器具，校准日期不得早于计划建立的本机日期，
# 且未被用于完成其他计划。再次用同一证书完成同一计划返回原结果。
ledger -f 我的台账.json complete --number PL-2026-01 --certificate C-2026-01

# 校准待办：默认列出全部未结束计划，也可 --instrument 按器具筛选；
# 按计划日期从早到晚、同日按器具编号排列，标记每次查询按本机日期重新判断。
ledger -f 我的台账.json todos
ledger -f 我的台账.json todos --instrument M-001
```

## 判定规则

- **合格 / 超差**：由测得误差的绝对值与器具允许误差自动比较，等于限值算合格，
  超过限值明确显示“超差”，录入者不能自行选择结论。
- **最近证书**：按校准日期确定，与录入先后无关；补录较早证书只增加历史。
  最近证书超差或到期时，不会回退到更早的合格证书。
- **到期**：有效期截止日当天起即到期；每次查询和申请都按本机当前日期重新判断。
- **同号证书**：同号且全部业务字段一致时返回原证书、不增加历史；
  同号内容不同报冲突且不改动已有数据。
- **同日限制**：同一器具同一天不接受两张不同编号的证书。
- **历史冻结**：使用申请被拒绝时记录申请时间、结果与当时全部原因；
  之后补录证书或切换状态都不会改写历史拒绝原因。
- **计划唯一性**：计划编号全台账唯一，即使对应已完成或已取消的计划也不能复用；
  每件器具最多有一项未完成、未取消的计划，需要继续安排时先结束旧计划再建立新计划。
- **建立时间取申请开始时刻**：每次建立计划只在开始处理时取一次本机时间，计划日期
  “不早于今天”的判断与正式保存的建立时间都按这一时刻；即使保存完成时已跨过午夜，
  建立时间仍属于申请开始的日历日期，当天计划不会被记成次日建立。该时刻不延续到
  下一次申请：下次建立重新按当时的本机日期判断，已过去的日期仍被拒绝。
- **计划改期与取消**：只有未结束的计划能改期或取消，且都必须填写非空原因；
  新日期不能早于操作当天。每次改期保留前后日期、操作时间和原因；取消保留原计划、
  取消时间和原因。已完成或已取消的计划不能再改期、取消或重新开启。
- **改期时间取申请开始时刻**：每次改期申请只在开始处理时取一次本机时间，新日期
  “不早于今天”的判断与改期历史里的操作时间都按这一时刻，操作时间保留当时的本机
  时区偏移；即使校验与写盘之间跨过午夜，日期仍按申请开始的日历日期合法，改期记录
  也不会被记成次日发生，前后日期与原因同样属于本次申请。该时刻不延续到下一次申请：
  次日重新申请改到已经过去的日期仍按当时的本机日期拒绝，即使该日期恰好等于当前
  计划日期也不能绕过日期要求；被拒绝的申请不留下原因或操作时间，既有改期记录的
  日期、原因和时间不被重写。再次改期成功时，新增记录从最后成功保存的日期接到新
  日期，操作时间取本次新申请而非上一条记录的时间。
- **停用不影响计划**：停用器具不会自动取消计划，其计划仍可查询、改期、取消和完成。
- **证书完成计划**：证书必须属于该器具、校准日期不得早于计划最初建立的本机日期、
  且不能已用于完成其他计划。超差证书也能表示校准工作已完成，但器具是否可用仍按
  现有状态、最近证书结论和有效期判断，计划不改变允许误差或证书。同证书重复完成
  同一计划返回原结果，不增加记录或刷新完成时间；仅录入证书不会自动完成计划。
- **待办标记**：计划日在今天标“今天需校准”，已过标“逾期”，未来标“未到计划日”，
  每次查询按本机日期重新判断，查询不产生使用记录。旧台账没有计划时按无计划处理。
- **无半份记录**：任何无效录入都在写盘前被拒绝，台账文件采用临时文件原子替换。
  已通过业务校验的录入若遇到台账文件无法写入或替换，明确返回保存错误：内存中的
  台账与文件都保持录入前状态，失败的证书不进入历史、不占用证书编号或该器具当天
  的位置，也不会被此后其他成功保存的操作顺带写入；文件仍不可写时再次提交仍报保存
  失败（不会被当成重复证书跳过），恢复可写后无需重新打开台账，重新提交才作为新
  证书录入，只有保存成功才参与最近证书与使用资格判断。器具登记同样只有保存成功才算
  正式登记：编号、名称与允许误差均合法但台账文件无法写入或替换时，明确报文件读写错误
  （命令行普通输出与 --json 模式均退出码 2，与空白内容、负数或非有限允许误差、编号
  重复等业务或参数错误相区别），不返回已登记的器具结果，也不输出登记成功或
  accepted: true；失败的新器具不进入列表、不占用编号，继续查询同一台账的器具列表与
  登记前一致（无论此前已有器具还是首次登记新台账），按失败编号核对、申请使用或安排
  校准都报告器具不存在，也不会被此后其他成功保存的操作顺带写入。文件仍不可写时再次
  提交该编号的合法内容继续报保存错误，不会因上一轮失败而变成编号重复；未通过原有
  校验的申请仍报原有业务或参数错误。恢复可写后无需重新打开台账，重新提交且保存成功
  才新增一件待校准器具，登记时间、名称与允许误差取本次成功提交的内容，不沿用失败
  申请；成功后再次登记同号仍按编号唯一拒绝，此前器具的状态、证书、计划及历史使用
  记录不受失败登记影响。改期同样只有保存成功才生效：
  保存失败报文件读写错误（命令行退出码 2，与日期或原因不符合要求的业务拒绝退出码
  1 相区别），不返回成功的计划结果，当前计划日期与待办标记不变，失败申请的原因和
  时间不进入改期历史，也不会被此后其他成功保存的操作顺带写入；恢复可写后在同一台账
  重新提交才生效，只新增一条从最后成功保存的日期到新日期的记录，时间取本次成功操作。
  用证书完成计划同样只有保存成功才算完成：保存失败报文件读写错误（命令行普通输出与
  --json 模式均退出码 2，与证书不符条件的业务拒绝退出码 1 相区别），不返回成功的
  计划结果，也不能被标成重复完成；计划仍为未完成并留在待办，完成时间与关联证书编号
  保持操作前的值，计划日期、已有改期记录和待办日期标记不变，该证书也不被算作已用于
  完成计划，失败信息同样不会被此后其他成功保存的操作顺带写入。文件仍不可写时再次
  提交继续报保存错误（不会跳过保存返回“此前已完成”）；恢复可写后无需重新打开台账，
  重新提交才真正完成并移出待办，核对中的关联证书与完成时间取本次成功操作而非失败
  时刻。真正保存成功后再用同一证书提交，才幂等返回原结果并保留原完成时间。取消计划
  同样只有保存成功才生效：计划符合取消条件但台账文件无法写入或替换时，明确报文件
  读写错误（命令行普通输出与 --json 模式均退出码 2，与计划不存在、已结束或原因空白
  的业务拒绝退出码 1 相区别），不返回取消成功的计划；计划仍为取消前的未完成状态并
  留在待办，当前计划日期、最初计划日期、说明与已有改期记录保持原样，取消时间和原因
  不留下本次申请的内容，也不会被此后其他成功保存的操作顺带写入。文件仍不可写时再次
  提交继续报保存错误（不会被当成“已结束”拒绝）；恢复可写后无需重新打开台账，重新
  提交合法申请才真正取消并移出待办，核对中的取消时间和原因取本次成功提交而非失败
  那次。状态切换
  同样只有保存成功才生效：目标状态合法且与最后成功保存的状态不同时，若台账文件无法
  写入或替换，明确报文件读写错误（命令行普通输出与 --json 模式均退出码 2，不输出
  已切换成功的结果），器具仍保持最后成功保存的状态——同一台账随后的列出、按器具核对、
  待办与当前能否使用都按保留下来的状态判断（停用器具即使有合格未到期证书，失败切换为
  在用后仍显示停用、原因仍含停用；在用器具失败切换为停用或待校准也不提前受限，证书
  超差、到期或缺失的限制仍按既有规则判断）；文件仍不可写时再次提交相同目标状态仍报
  保存错误，不会把上一次未保存的状态当成已生效而直接成功。恢复可写后无需重新打开台账，
  只有再次成功提交切换，目标状态才在查询和使用判断中生效；若恢复后先完成另一项正常
  保存，先前失败的状态也不会被顺带写入。请求状态本来就等于最后成功保存的状态时直接
  返回成功，不额外写盘。状态切换不修改证书、校准计划或历史使用记录，停用后的历史可查，
  过去拒绝使用时记录的原因不会随切换重写。使用申请同样只有本次记录保存成功才算提交
  完成：器具编号存在但台账文件无法写入或替换时，明确报文件读写错误（命令行普通输出与
  --json 模式均退出码 2，与获准退出码 0、业务拒绝退出码 1 相区别），不返回已提交成功
  的使用结果，也不把这种情况输出成已留痕的业务拒绝——即使器具停用、缺少证书、最近证书
  超差或到期等拒绝原因已经得出，只要记录没有保存成功，本次操作仍报告保存失败。失败后
  继续使用同一台账，全部使用记录与按器具核对中的被拒绝记录都只有此前成功保存的申请，
  本次失败申请的时间、允许结果与拒绝原因不进入历史，已有记录的数量、内容和原因保持
  原样；恢复可写后若先完成一次正常的状态切换或其他既有保存操作，失败的申请也不会被
  顺带写入，器具登记信息、证书和校准计划不因这次失败发生变化。恢复可写后无需重新打开
  台账，在同一台账重新申请且保存成功时只增加这次新提交的一条记录，时间、结果和全部
  原因取重新申请当时的情况；若两次申请之间器具状态或证书已经改变，按新的实际情况判断，
  不沿用失败那次的结论。建立计划同样只有保存成功才算建立：器具与计划内容
  都符合要求但台账文件无法写入或替换时，明确报文件读写错误（命令行普通输出与
  --json 模式均退出码 2，与编号重复、器具已有未结束计划或日期、说明不符合要求
  的业务拒绝退出码 1 相区别），不返回已建立成功的计划；失败的新计划既不占用
  计划编号，也不占用该器具唯一的未结束计划名额——同一台账随后的计划查询、待办
  与按器具核对都只能看到此前已经保存的计划，此前保存的计划及其改期、取消、完成
  信息保持原样，器具状态、证书和使用记录也不受此次申请影响。文件仍不可写时再次
  提交相同编号和内容继续报保存错误（不会被上次失败留下的计划当成编号重复或器具
  已有计划挡住）；未通过业务检查的申请仍按原有方式拒绝，不能因台账不可写而被混成
  保存失败。恢复可写后无需重新打开台账，重新提交且当时仍符合原有条件（计划日期以
  本次申请的本机今天判断，原日期已经过去则明确拒绝且不新增计划）才正常建立一项
  未完成计划并出现在该器具核对和待办中，建立时间取本次成功申请的时间；此前失败的
  申请不会提前成为正式计划，即使恢复可写后先做了一次正常的状态切换，随后保存的
  台账里也不会夹带它。
